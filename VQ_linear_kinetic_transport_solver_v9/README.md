# VQ Linear Kinetic Transport Solver v9

Version 9 implements the two revisions recommended after the discussion with Ryan McClarren:

1. **Mixed angular order in the collision split.** The uncollided equation can use a high-order quadrature `N_u`, while the collided equation uses a lower-order quadrature `N_c`. Moment-preserving residual quantization is applied only to the low-order collided field.
2. **Process-level peak-memory measurements.** Peak memory is measured from resident set size (RSS) and unique set size (USS) with `psutil`, with Linux `VmHWM` and `resource.ru_maxrss` recorded as independent high-water marks. Python `tracemalloc` is retained only as a separately labelled Python-allocation diagnostic.

## Why the line-source benchmark?

The v9 mixed-order production experiment uses the **2D line-source problem**. It gives the cleanest test of the intended hybrid mechanism: the uncollided field retains sharp ballistic/ray structure and therefore benefits from high angular order, whereas the scattered field is a more plausible low-order compression target. The lattice and hohlraum are retained as standard same-order benchmarks and are natural follow-up mixed-order tests after the transfer mechanism is validated.

## Installation

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

## Main commands

Quick validation:

```bash
make test
make mixed-order-smoke
```

Production line-source study:

```bash
make mixed-order
```

The default production configuration is

```text
Nx = Ny = 201
N_u = 32  (uncollided)
N_c = 8, 16  (collided)
bits = 5, 8
```

Override from the command line, for example:

```bash
make mixed-order NX=101 NU=32 NC=8 BITS=5
```

Run one case in a fresh process:

```bash
PYTHONPATH=src python scripts/run_case.py \
  --problem line_source --nx 51 --method uc \
  --uncollided-order 16 --collided-order 4 \
  --compression moment --bits 5 --preserve phi_current \
  --out results/example
```

## Outputs

`make mixed-order` creates:

```text
results/v9_mixed_order/
  raw/<case>/summary.json
  raw/<case>/solution.npz
  data/mixed_order_run_summaries.csv
  data/mixed_order_errors.csv
  figures/mixed_order_scalar_flux.png
  figures/mixed_order_5bit_error.png
  figures/mixed_order_accuracy.png
  figures/mixed_order_peak_rss.png
```

Each case is executed as a **fresh subprocess**, so process high-water marks are not contaminated by earlier cases in the matrix.

## Memory fields

The JSON and CSV output distinguish:

- `rss_start_mib`: resident memory immediately before the measured solve
- `rss_peak_mib`: maximum sampled resident memory
- `rss_delta_peak_mib`: peak RSS above the starting RSS
- `uss_start_mib`, `uss_peak_mib`, `uss_delta_peak_mib`: process-private memory when supported
- `vmhwm_mib`: Linux `/proc/self/status` high-water mark
- `ru_maxrss_mib`: platform `resource.getrusage` high-water mark
- `python_tracemalloc_peak_mib`: Python allocator peak only; this is **not** the process peak
- `memory_measurement_method`: methods available on the platform

For paper tables, use RSS/USS or the fresh-process high-water mark. Do not label `tracemalloc` as total process memory.

## Mixed-order transfer

At the end of each time step, the low-order collided angular history is transferred to the high-order grid used by the next uncollided solve. The transfer uses nearest-direction reconstruction followed by a weighted affine correction that preserves the selected moments exactly:

```text
phi, Jx, Jy on N_c  ==  phi, Jx, Jy after transfer to N_u
```

This is tested in `tests/test_transfer.py`.

## Important scope

The current solver uses isotropic scattering in the included benchmarks. The mixed-order source coupling therefore needs the scalar flux. Current is additionally protected for diagnostics and diffusion-scale structure. For a more general angular scattering kernel, every moment used by the discrete scattering operator must be protected, or a separate angular transfer/source approximation must be specified.

## Reproducibility note

The v9 archive is a clean source package. It does not bundle the large v8 numerical result archive. All v9 mixed-order results are regenerated by the commands above.
